# Запуск legacy CRM: PHP 5.3.3 и Apache/CGI

## Задача

Во время практики требовалось подготовить Docker-окружение для существующей CRM. Приложение зависело от PHP 5.3.3, заданного набора расширений и правил `.htaccess`. Требовалось сохранить совместимость, а не переносить приложение на новый PHP.

Первым этапом была сборка PHP из исходников с параметрами существующего окружения. Следующим — запуск приложения на предоставленном демонстрационном сервере с Apache и MariaDB ветки 5.5.

## Неисправность

При открытии страницы появлялись предупреждения о незаданном часовом поясе. Их вывод приводил к ошибкам `headers already sent`, мешавшим запуску сессии и отдаче страницы входа.

Проверка PHP из терминала показывала загруженный `php.ini`. Однако `php_ini_loaded_file()` в веб-запросе возвращал пустое значение. Поэтому проверка `php -v` или `php --ini` из CLI не позволяла считать настройку приложения завершённой.

## Подход

Нужно отдельно проверять два пути исполнения: CLI и CGI, запускаемый Apache от `www-data`. В исходном окружении конфигурация располагалась под `/root`, что требовало проверки прав на весь путь, а также фактических параметров CGI-wrapper. Сохранившиеся материалы не доказывают единственную первопричину на сервере; проблема описывается как расхождение загрузки конфигурации CLI и CGI.

В публичном стенде бинарные файлы установлены в `/opt/php533`, а конфигурация — в `/etc/php533/php.ini`. Wrapper явно задаёт путь через `-c`. Часовой пояс определён в этом файле. HTTP-проверка подтверждает, какой файл загружен именно веб-обработчиком.

## Исторический результат

На демонстрационном сервере удалось открыть страницу CRM; проверка выполнялась через браузер и `curl`. Руководитель просмотрел развёртывание и подтвердил, что результат выглядит рабочим. PHP работал внутри Apache-контейнера, поэтому отдельный выключенный PHP-контейнер не участвовал в обработке запросов.

Это подтверждение демонстрационного запуска. Оно не означает проверки всех функций CRM, производительности или готовности к промышленной эксплуатации.

## Что доступно в этом репозитории

Итоговая серверная конфигурация не сохранилась в исходной локальной папке. Для публичного примера подготовлены новая конфигурация Apache/CGI, небольшая страница клиентов, искусственная БД и интеграционные проверки. Код и данные организации не используются.

Версия PHP и функциональные параметры его сборки сохранены. Пути установки адаптированы; публичная MariaDB 5.5.64 отличается от запрошенного на сервере пакета 5.5.52. Автоматические проверки относятся только к этому демонстрационному приложению.

## Практический вывод

Успешная сборка интерпретатора и рабочий CLI — промежуточный результат. При запуске приложения нужно проверить фактический веб-обработчик, его пользователя, загрузку конфигурации, сессии, заголовки и соединение с БД. Поэтому центральная проверка этого стенда идёт по всей цепочке HTTP → Apache → CGI → PHP → MariaDB.
